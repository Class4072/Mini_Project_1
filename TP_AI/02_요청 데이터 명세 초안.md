# 일정 생성 요청 데이터 명세 초안

> [!warning] 임시값
> 필드 이름과 코드값은 FE 개발용 임시값. 회의에서 확정되면 [[03_회의 후 수정 위치]] 의 파일만 고치면 됨.

## 요청
`POST /api/v1/itinerary/itineraries/generate` (임시) · `Content-Type: application/json` · 타임아웃 120초

```json
{
  "regionCodes": ["6"],
  "startDate": "2026-11-01",
  "endDate": "2026-11-03",
  "companionType": "FRIENDS",
  "travelerCount": 3,
  "transport": "PUBLIC_TRANSIT",
  "themes": ["FOOD", "NATURE"],
  "placesPerDay": "NORMAL",
  "startTime": "NORMAL"
}
```

## 필드
| 필드            | 형태               | 필수  | 값                           | 비고                              |
| ------------- | ---------------- | --- | --------------------------- | ------------------------------- |
| regionCodes   | 문자열 배열           | O   | 지역 코드 1개                    | 여러 지역 확장 대비 배열. TourAPI 지역코드 가정 |
| startDate     | 문자열 `YYYY-MM-DD` | O   | 오늘(KST) 이후                  |                                 |
| endDate       | 문자열 `YYYY-MM-DD` | O   | startDate 이상                | 당일치기는 같은 날                      |
| companionType | 코드               | O   | 아래 표                        |                                 |
| travelerCount | 정수               | O   | 혼자=1, 그 외 2 이상              | 상한 없음(개발 단계)                    |
| transport     | 코드               | O   | CAR / PUBLIC_TRANSIT / WALK | 동선 계산에 영향                       |
| themes        | 코드 배열            | O   | 0~3개                        | 빈 배열 = 골고루                      |
| placesPerDay  | 코드               | O   | RELAXED / NORMAL / PACKED   | 기본 NORMAL                       |
| startTime     | 코드               | O   | EARLY / NORMAL / LATE       | 기본 NORMAL                       |

- 사용자가 입력하지 않는 값: 날씨, 운영시간 (백엔드가 지역·날짜로 조회), 사용자 ID (로그인 구현 후 토큰에서)

## 코드값
	### 지역 (regionCodes)
서울 1 · 인천 2 · 대전 3 · 대구 4 · 광주 5 · 부산 6 · 울산 7 · 세종 8 · 경기 31 · 강원 32 · 충북 33 · 충남 34 · 경북 35 · 경남 36 · 전북 37 · 전남 38 · 제주 39

### 동행 (companionType)
| 코드 | 화면 |
|---|---|
| SOLO | 혼자 |
| COUPLE | 연인·부부 |
| FRIENDS | 친구 |
| FAMILY_WITH_KIDS | 아이와 함께 |
| FAMILY_WITH_PARENTS | 부모님과 함께 |
| GROUP | 단체 |

### 이동수단 (transport)
| 코드 | 화면 | 화면 설명 |
|---|---|---|
| CAR | 자동차 | 주차할 수 있는 곳 위주로, 조금 멀어도 한 번에 이어서 돌아요. |
| PUBLIC_TRANSIT | 대중교통 | 역·정류장에서 가까운 곳 위주로 짜요. |
| WALK | 도보 위주 | 걸어서 이동할 수 있는 거리 안에서 묶어요. |

### 취향 (themes)
| 코드 | 화면 | 연결할 TourAPI 분류 (가정) |
|---|---|---|
| NATURE | 자연·풍경 | 자연 |
| HISTORY_CULTURE | 역사·문화 | 인문(역사), 문화시설 |
| FOOD | 맛집 | 음식점 |
| CAFE | 카페 | 음식점 중 카페·찻집 |
| ACTIVITY | 체험·액티비티 | 체험관광지, 레포츠 |
| SHOPPING | 쇼핑 | 쇼핑 |
| FESTIVAL | 축제·공연 | 축제공연행사 (여행 날짜에 열리는 것만) |
| HEALING | 휴식·힐링 | 휴양관광지 |

### 하루 몇 곳 (placesPerDay)
| 코드 | 화면 |
|---|---|
| RELAXED | 2~3곳 · 여유롭게 |
| NORMAL | 4~5곳 · 적당히 (기본) |
| PACKED | 6곳 이상 · 알차게 |

### 시작 시간 (startTime)
| 코드 | 첫 일정 시작 | 화면 |
|---|---|---|
| EARLY | 08:00 | 아침 일찍 |
| NORMAL | 10:00 | 보통 (기본) |
| LATE | 11:00 | 느긋하게 · 퇴실 후 |

종료는 모두 21:00

## 응답 (임시)
```json
{ "itineraryId": "123" }
```
- 성공 시 `/itinerary/{itineraryId}` 로 이동해 일정 화면에서 다시 조회하는 방식 가정
- 실패 시 화면 문구: "일정을 만들지 못했어요. 잠시 후 다시 시도해주세요." / 타임아웃: "일정 만들기가 오래 걸려 멈췄어요. 잠시 후 다시 시도해주세요."

## 같이 정할 것
1. 코드값을 영문 코드로 보낼지 한글로 보낼지
2. startTime 을 코드로 보낼지 시각(`"10:00"`)으로 보낼지
3. 응답에 일정 전체를 바로 줄지, id 만 주고 따로 조회할지
4. 생성이 오래 걸리면 비동기(job id + 상태 조회)로 바꿀지
5. 목록에 없는데 알고리즘에 필요한 값 / 있는데 안 쓰는 값
