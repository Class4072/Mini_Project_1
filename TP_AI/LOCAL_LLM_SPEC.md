# 🤖 로컬 LLM(Ollama) 역할 및 태스크 명세서 (`LOCAL_LLM_SPEC.md`)

본 문서는 여행 일정 생성 AI 파이프라인에서 **로컬 LLM(Ollama)이 수행해야 하는 핵심 임무, 입력 데이터 규격, 최종 출력 JSON 스펙, 모델 환경설정 가이드**를 정리한 명세서입니다.

---

## 🏛️ 1. 시스템 분업 구조 (Architecture Role Division)

우리 시스템은 **[백엔드: 팩트 검증 및 물리 제약 계산] ➡️ [로컬 LLM: 지능적 큐레이션 및 스토리텔링]**의 RAG 분업 구조를 취합니다.

```
[백엔드 (FastAPI + pgvector + 기상청 DB)]
  - 팩트 날씨 DB 조회 (기상청 예보 1순위)
  - 시맨틱 벡터 검색 & 날씨/동행자 가중치 부여
  - 거리/이동시간 계산 (Haversine)
  - 후보 장소 12~16곳 압축 (토큰 다이어트)
                 │
                 ▼ [후보 장소 목록 + 여행 조건 전달]
[로컬 LLM (Ollama / Qwen 2.5 / EXAONE 등)]
  - 🎯 후보 장소 중 최종 방문지 픽(Pick)
  - 🗺️ 일자별(Day) 배분 및 시간대별 세부 동선(Step) 순서화
  - ⏱️ 현실적인 체류 시간(stayTimeMinutes) 배분
  - ✍️ 날씨·동행자 맞춤형 추천 사유(reason) 작성
  - 🏷️ 여행 패키지 타이틀(tripName) 및 날씨 요약(weatherSummary) 작명
                 │
                 ▼ [순수 JSON 응답]
[백엔드 (자가보정 및 안전망 검증)]
  - JSON 문법 수리 및 환각 장소 검출 (불일치 시 자동 재요청)
  - 최종 21:00 시각 클램핑 후 클라이언트에 응답
```

## 🎯 2. 로컬 LLM이 실제로 수행하는 핵심 5대 작업

### ① 최종 방문 장소 선별 및 픽 (Place Picking)
- 백엔드가 건네준 후보 장소(12~16개) 중, 여행 일수와 밀도에 맞춰 **실제 방문할 최적의 장소(예: 2박 3일 총 8~10곳)를 최종 채택**하고 불필요한 장소는 제외합니다.
- *원칙: 반드시 전달받은 후보 목록 내의 장소 ID와 이름만 사용해야 합니다 (환각 금지).*

### ② 일자별(Day) 배분 및 세부 방문 순서(Step Sequencing)
- 채택한 장소들을 `Day 1`, `Day 2` 등으로 나누고, 하루 중 방문할 순서(`step: 1 ➡️ 2 ➡️ 3 ➡️ 4`)를 논리적으로 배치합니다.
- **거점 앵커링 반영**: Day 1 첫 일정은 출발 거점(KTX역, 공항 등)과 가까운 곳부터 시작하고, 마지막 날은 복귀 거점과 가까운 곳으로 마무리합니다.
- **식사 및 카페 시퀀스**: 점심(12:00~13:30)과 저녁(18:00~19:30)에는 식당을 배치하고, 식사 직후에는 바로 인접한 카페나 문화 산책로가 이어지도록 순서를 배치합니다.

### ③ 유기적인 시간 배분 (`startTime`, `endTime`, `stayTimeMinutes`)
- 장소 카테고리에 맞는 현실적인 체류 시간을 배분합니다:
  - 대형 미술관/아쿠아리움/테마파크: `90 ~ 120분`
  - 식사: `60 ~ 90분`
  - 카페/디저트: `45 ~ 60분`
  - 산책로/전망대: `40 ~ 60분`
- 하루 일정은 지정된 시작 시각(기본 10:00)부터 시작하여 **21:00경 종료**되도록 시간표를 촘촘히 엮습니다.

### ④ 날씨·동행자 맞춤형 추천 사유 (`reason`) 작성
- 기계적인 텍스트가 아닌, **날씨 상황과 동행자(부모님, 아이, 연인, 친구 등)의 특성을 살린 감성적이고 설득력 있는 문장**을 생성합니다.
- *작성 예시:*
  - (우천 + 부모님): *"오후 비 예보에 맞춰 계단이 없고 편안하게 바다를 감상할 수 있는 실내 오션뷰 카페로 선정했습니다."*
  - (맑음 + 연인): *"노을 지는 시간대에 맞춰 로맨틱한 해안 산책로를 걸을 수 있도록 오후 마지막 코스로 배치했습니다."*

### ⑤ 여행 패키지 타이틀(`tripName`) 및 날씨 요약(`weatherSummary`) 브랜딩
- 전체 일정을 아우르는 매력적인 여행 기획 제목과 날씨 대비 팁을 작명합니다.
- *출력 예시:*
  - `tripName`: `"촉촉한 가을비와 함께하는 부산 해안 감성 힐링 2박 3일"`
  - `weatherSummary`: `"1일차 오후 강수확률 80%로 실내 문화공간 및 오션뷰 카페 위주로 동선을 안전하게 구성했습니다."`

## 📥 3. LLM 입력 데이터 명세 (Prompts)

### 1) 시스템 프롬프트 (System Prompt)
LLM에게 페르소나와 작성 원칙, 출력 JSON 규격을 강제합니다.

```text
당신은 대한민국 최고의 AI 여행 플래너 "Trp Engine"입니다.
주어진 장소 후보군과 여행 조건, 당일 기상청 날씨/계절 정보를 종합 분석하여, 
여행자가 지치지 않고 날씨를 즐길 수 있는 최적의 시간대별 여행 일정을 설계해야 합니다.

[작성 원칙]
1. 반드시 전달받은 후보 장소 목록(Candidate Places) 내에서만 선택하십시오. (환각 금지)
2. 날씨가 우천(RAIN)일 경우 반드시 실내 장소 및 비 풍경이 좋은 장소 위주로 배치하고, 추천 사유에 날씨 팁을 명시하십시오.
3. 점심 시간(12:00~13:30)과 저녁 시간(18:00~19:30)에는 반드시 음식점이 배치되어야 하며, 식사 직후에는 멀리 이동하지 않고 인근의 [카페/디저트] 또는 [산책/전시 등 컨텐츠]가 순서대로 자연스럽게 이어지도록 설계하십시오.
4. 출력 형식은 다른 설명(인사말, 마크다운 등) 없이 반드시 순수한 JSON 형식만 반환하십시오.
```

### 2) 유저 프롬프트 (User Prompt 예시)
백엔드가 가공하여 주입하는 동적 데이터입니다.

```text
### [여행 요청 조건]
- 대상 지역: 부산
- 여행 기간: 2026-11-01 ~ 2026-11-02 (2일)
- 동행 유형: 부모님 (2인, 태그: 여유로운, 편안한 동선)
- 이동 수단: 대중교통
- 여행 테마: 힐링, 미식
- 하루 일정 밀도: 하루 약 4곳 권장
- 첫 일정 시작 시각: 10:00부터 시작하여 21:00경 종료
- 출발 거점 (시작지점): 부산역 (도착 후 첫 번째 방문지는 이 거점에서 인접하고 효율적인 장소로 배치)

### [기상청 예보 날씨]
- 2026-11-01: RAIN (기온: 18.5℃, 강수확률 80%)
- 2026-11-02: SUNNY (기온: 20.0℃, 강수확률 10%)

### [선별된 후보 장소 목록 (Candidate Places)]
1. ID: 101 | 부산 아쿠아리움 | 실내 전시 | 실내 | (35.1593, 129.1611) | 해운대 해변에 위치한 대형 실내 해양 수족관
2. ID: 102 | 해운대 기와집 대구탕 | 한식당 | 실내 | (35.1610, 129.1630) | 부모님 식사에 적합한 자극적이지 않고 시원한 대구탕 전문점
3. ID: 103 | 랑데자뷰 해운대점 | 카페 | 실내 | (35.1605, 129.1625) | 오션뷰와 제주 감성의 인테리어가 돋보이는 편안한 카페
... (총 12~16개)
```

## ⚙️ 5. Ollama 구동 및 커스텀 모델 설정 가이드

### 1) 추천 모델
- **1순위**: `qwen2.5:7b` (또는 `14b`) - JSON 포맷 준수율 및 지시 수행력 최상위
- **2순위**: `exaone3.5:7.8b` - LG AI 연구원 한국어 특화 모델, 문장 품질 우수

### 2) `Modelfile` 작성 (컨텍스트 확장 및 파라미터 고정)
긴 후보 장소 목록을 처리하기 위해 `num_ctx`를 반드시 `8192` 이상으로 설정합니다.

```dockerfile
# Modelfile
FROM qwen2.5:7b

# 컨텍스트 창 8k로 확장 (장소 목록 잘림 방지)
PARAMETER num_ctx 8192

# 환각 방지 및 지시 엄수를 위한 낮은 온도
PARAMETER temperature 0.2
PARAMETER top_p 0.9

# 시스템 기본 프롬프트
SYSTEM """당신은 대한민국 최고의 전문 여행 플래너 AI입니다.
주어진 후보 장소 목록 내에서만 엄격히 선택하여 오차 없는 유효한 JSON 형식으로 일정을 기획합니다."""
```

```bash
# 모델 빌드 및 실행
ollama create travel-llm -f Modelfile
ollama run travel-llm
```

### 3) 프로젝트 `.env` 바인딩
```bash
LLM_PROVIDER=ollama
LLM_MODEL_NAME=travel-llm
OLLAMA_BASE_URL=http://localhost:11434  # 원격 서버일 경우 http://<IP>:<PORT>
LLM_TIMEOUT_SECONDS=60.0               # 로컬 GPU 추론 대기 시간 설정
```

## 🛡️ 6. 백엔드의 3중 안전망 (Safety Guards)

로컬 LLM이 혹시 실수를 하더라도 백엔드에서 아래와 같이 안전하게 보정합니다:

1. **환각 검증 (`verify_candidates_integrity`)**:
   - LLM이 임의로 지어낸 장소가 감지되면 즉시 실패 처리하고, *"후보군에 없는 장소를 제외하고 다시 작성하라"*는 오류 피드백을 담아 **최대 3회 자동 재요청(Self-Correction)**합니다.
2. **JSON 자동 수리 (`repair_json_syntax`)**:
   - 끝 쉼표(`,`) 누락이나 마크다운 백틱(```json)이 포함되어도 파이썬 정규식 파서가 자동으로 복구합니다.
3. **시간 클램핑 (`clamp_schedule_time`)**:
   - 21:00 이후로 초과된 일정은 21:00 이전으로 자동 보정합니다.
4. **최종 안전 Fallback (`build_fallback_schedule`)**:
   - LLM 서버 다운 등 비상 상황 시에도 에러를 뿜지 않고 알고리즘이 생성한 정상 일정을 100% 반환합니다.
