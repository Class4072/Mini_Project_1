# 0004. 임베딩 DB·차원 불일치 (aidb vs tour_db)

- 날짜: 2026-11-19
- 상태: **미결** (AI·배치 담당과 결정 필요)
- 관련: [database/DATABASE.md](../database/DATABASE.md), `db/migration/V1__init_schema.sql`

## 배경

목표 설계와 실제 코드가 서로 다른 DB 를 보고 있다.

| | 목표 설계 (DATABASE.md, V1 마이그레이션) | 현재 코드 (develop 의 AI·배치) |
| :--- | :--- | :--- |
| DB | `tour_db` 하나를 모든 서비스가 공유 | `aidb` |
| 장소 테이블 | `tour_places`, `tour_place_details` | `place`, `place_detail` |
| 임베딩 | `tour_embeddings` vector(**1536**) (text-embedding-3-small) | `travel_spots`·`document_chunks` vector(**768**) (ko-sroberta) |
| 계정 | `tp_owner`·`tp_backend`·`tp_batch`·`tp_ai` | 관리자 계정 |

BE 는 `tour_db` 를 쓰므로, 지금 상태로는 BE 가 배치가 모은 장소·임베딩을 읽지 못한다.

## 현재 운영 (임시)

- 맥미니 배포에서 BE 는 `tour_db`, AI·배치는 `aidb` 에 연결해 각자 동작하게 했다.

## 정해야 할 것

1. 어느 쪽으로 통일할지 (AI·배치를 `tour_db` 로 옮길지, 설계를 `aidb` 구조에 맞출지)
2. 임베딩 모델·차원 (768 ko-sroberta 유지 vs 1536 text-embedding-3-small 등)
3. 옮긴다면 기존 `aidb` 데이터(장소 약 5만 건) 이관 방법
