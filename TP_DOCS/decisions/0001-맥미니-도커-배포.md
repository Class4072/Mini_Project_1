# 0001. 맥미니 도커 배포와 공개 방식

- 날짜: 2026-11-17 ~ 2026-11-19
- 상태: 결정
- 관련: PR #4 (도커·CI), [infra/macmini-deploy.md](../infra/macmini-deploy.md), [infra/cloudflare-tunnel.md](../infra/cloudflare-tunnel.md)

## 배경

팀 회의에서 서비스별 도커 이미지 생성과 CI 연결을 기능 개발 전에 먼저 하기로 했다.
기능이 거의 없을 때 "빌드 → 이미지 → 실행"이 끝까지 도는지 확인하려는 목적.
배포할 곳은 팀원 집의 맥미니(DB·Ollama 가 이미 떠 있음).

## 결정

1. 서비스 4개(FE·BE·AI·배치)를 각각 이미지로 만들고, 루트 `docker-compose.yml` 하나로 함께 띄운다.
2. **레지스트리 없이** 맥미니에서 직접 빌드·실행한다. 태그는 커밋 SHA + `dev`.
3. DB(pgvector)·Ollama 는 컨테이너로 옮기지 않고 맥미니 호스트에 있는 것을 `host.docker.internal` 로 쓴다.
   Ollama 는 도커 안에서 맥 GPU(Metal)를 못 써서 느리기 때문.
4. 환경값은 이미지에 넣지 않고 실행 시 `.env` 로 주입한다. FE 의 `VITE_*` 만 빌드 시 들어간다(카카오 JS 키는 원래 공개되는 키).
5. 외부 공개는 Cloudflare 터널로 `tp.ricebug.dev` 하나만. 포트는 모두 `127.0.0.1` 에만 연다.
6. 배포(CD) 자동화는 보류. `scripts/deploy-macmini.sh` 로 수동 배포.

## 고려한 대안

- GHCR 등 레지스트리 + 자동 배포: 맥미니 한 대라 이득이 적고, 맥미니에서 직접 빌드하면 arm64 문제도 없음
- 공유기 포트포워딩: 집 IP 노출·공유기 설정 필요 → 터널이 더 단순하고 안전
- BE·AI 도 외부 공개: FE 가 `/api` 를 프록시하므로 불필요
