# 0002. CI 이미지 빌드 조건과 캐시

- 날짜: 2026-11-19
- 상태: 결정
- 관련: PR #5, [infra/ci.md](../infra/ci.md)

## 배경

PR #4 의 CI 가 BE 기준 4~6분 걸렸다. 단계별로 보니 상위는 전부 Docker 이미지 빌드였고, 캐시는 모두 miss 였다.

- PR 에서 만든 캐시는 `develop` 이 읽지 못한다 (GitHub Actions 캐시는 브랜치 단위)
- `setup-gradle` 은 기본 브랜치(main)에서만 캐시를 저장해서 `develop` 에서는 Gradle 캐시가 쌓이지 않았다
- AI·배치는 torch 레이어 때문에 캐시 내보내기만 30~45초

## 결정

1. PR 에서는 lint·test 만 하고, 이미지 빌드는 **Dockerfile·의존성 파일이 바뀐 서비스만** 한다. `develop` push 에서는 항상 빌드한다.
2. Docker 캐시 저장(`cache-to`)은 `develop` push 에서만. PR 은 읽기만 한다.
3. `setup-gradle` 의 `cache-read-only` 를 `develop` 이 아닐 때만 true 로.
4. BE 의 `ktlintCheck` 와 `test` 를 Gradle 한 번으로 실행.

## 고려한 대안

- CI 에서 이미지 빌드를 아예 빼고 맥미니 배포 때만 확인: 가장 빠르지만 이미지가 깨진 걸 배포 때가 돼서야 앎
- `mode=min` 캐시: Dockerfile 이 단일 단계라 줄어드는 게 거의 없음

## 결과·남은 일

- develop push 기준 이미지 빌드 BE 190s → 4s, AI 107s → 2s
- 남은 일: `be_image` 필터에 `db/migration/**`·`gradlew`·`gradle.properties` 추가
